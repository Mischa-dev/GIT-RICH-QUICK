# Plug in T3 Code

## Send an arcade contract to T3

Open **T3 Link** in the casino. Review or edit the brief, then choose **Open draft in T3 Code**. When opened from the agent desk, the editor brings your current brief along. T3's official prompt link opens the draft in its own client. Select your machine and project and press **Send** there to start a real run. The browser sends the draft text to `app.t3.codes` when you follow the link. This works on both the hosted game and the local version.

## Turn actual model use into a casino expense

On the machine that runs your T3 server, install Node 22.13 or newer. Clone this repo and run the bridge from inside the clone.

```sh
node server/t3.mjs
```

Open **http://127.0.0.1:7777**. In **T3 Link**, click **Find local threads**, pick a thread, then click **Pair meter**. Run a turn in that thread from your usual T3 client. Leave the casino tab open. The odometer polls every four seconds and charges one pretend TOK per 1,000 new reported model tokens. The amount left over rolls into the next update. Pairing establishes the starting reading, so previous usage is free. Disconnecting or refreshing the browser ends the meter session.

The bridge defaults to `~/.t3/userdata/statev2.sqlite` and honors `T3CODE_HOME`. For a customized T3 state location or a different port:

```sh
GRQ_T3_DB=/path/to/statev2.sqlite GRQ_PORT=7778 node server/t3.mjs
```

For a remote T3 host such as a Tailscale-connected NixOS server, run the bridge there and forward its loopback listener to your laptop. Replace `my-t3-host` with your SSH host.

```sh
ssh -N -L 7777:127.0.0.1:7777 my-t3-host
```

Then open `http://127.0.0.1:7777` on the laptop. Keep the bridge bound to loopback. The public game and the local game have separate browser saves because they have different origins.

### What the meter counts

T3 v2 stores per-provider-turn totals in its `orchestration_v2_projection_provider_turns` SQLite projection. The bridge opens that database read-only and watches the selected app thread. It uses the sum of reported `turnTokenUsage.inputTokens` and `outputTokens` from complete usage records, usually available when a turn settles. Cache reads/writes and reasoning are already included in these normalized figures. Local commands, partial or unavailable provider usage, and separately recorded child-thread usage do not contribute. Providers or older T3 builds without per-turn records can show zero.

The server returns recent active thread titles and IDs plus aggregate numeric readings to the local page. A disappearing signal retries automatically. Your actual agent keeps running if the casino wallet empties. Casino tokens have no effect on T3's model selection, permissions, account, quotas, or billing.
